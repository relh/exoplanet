# ASAS-SN access route: an operational alternative, not new photometry

The prior failed Sky Patrol V2 client endpoint does not establish that all ASAS-SN access is unavailable. The public Ohio State Sky Patrol homepage currently responds successfully and exposes its coordinate-based photometry request form. Its linked Hawaii V2 website remains unreachable in this environment. The working coordinate form includes an interactive CAPTCHA, so it is not an unattended replacement for the failed API. No challenge bypass or form submission was attempted. This is a service-route finding only: no target coverage, cadence, precision or light curve was obtained for either strongest candidate.

The [official client source](https://github.com/asas-sn/skypatrol/blob/master/pyasassn/client.py) still points at the previously failing port-9006 API; that source was read as text, not executed, and the same endpoint was not redundantly retried. The operational [Ohio State interface](https://asas-sn.osu.edu/) offers a separate request workflow and documents 8-arcsecond pixels with an approximately 15-arcsecond PSF; nearby-source blending therefore remains important. An HTTP-successful homepage does not prove its computation backend will complete or supply adequate photometry.

[documentation.json](documentation.json) records URLs, access times, response hashes and the Hawaii connection error. Raw responses live in ignored `data/strongest-external-access-20261012/`. The first local script was unfortunately named `inspect.py`, shadowing Python's standard-library module and failing during imports before requests completed; its source and errors are retained. Renaming it resolved the local import problem without changing any scientific result.

This pass did not submit a computation job or open flux. A future request requires a frozen observation/time-range choice, immutable clocks and timing profiles, time-system conversion, camera/filter baseline treatment and coverage/sensitivity gates before access. Sparse, blended ground-based measurements need not constrain a roughly 600-ppm TESS signal; no nonmatch, binary exclusion or planet support is inferred here.
